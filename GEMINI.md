# Правила разработки и сопровождения проекта Geo Routing Server

## 1. Правила версионирования (SemVer)
- **Мелкие правки и косметика**: изменение текстов, формулировок, перестановка пунктов меню, опечатки, комментарии — **НЕ повышают номер версии** (`SCRIPT_VERSION`). В коммитах указывать тег `[skip-version-check]`, чтобы автотесты CI/CD GitHub Actions не блокировали изменения.
- **Патч-версии (PATCH: x.y.Z)**: инкремент версии выполняется строго при исправлении реальных ошибок логики, багфиксах или завершённых доработках функционала. Не допускается инкремент версии на каждый промежуточный коммит.
- **Минорные версии (MINOR: x.Y.0)**: добавляются при внедрении новой функциональности (новые клиенты, поддержка протоколов, крупные модули).
- **Мажорные версии (MAJOR: X.0.0)**: при кардинальных изменениях архитектуры или нарушении обратной совместимости конфигураций.

## 2. Стандарты деплоя и совместимости с Docker UI (Arcane, Portainer и др.)
- Файл конфигурации `.env` должен создаваться и обновляться с правами **`0644`** (доступен на чтение для Docker-панелей и группы `docker`). Запрещено ставить блокирующие права `0600`.
- Файл `compose.yaml` должен иметь права **`0644`** и содержать явную директиву проекта `name: geo-routing-server`.
- Всегда поддерживать обратную совместимость с внешними веб-панелями управления контейнерами.
- Любые запросы к внешним интеграциям (например, Remnawave API) при выполнении на хосте должны иметь fallback на выполнение через запущенный контейнер (`docker exec`), если хост не находится во внутренней сети Docker.
